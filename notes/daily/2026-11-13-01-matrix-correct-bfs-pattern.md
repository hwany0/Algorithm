# 2026-11-13 01 Matrix: 정석 BFS 패턴

## 오늘의 핵심
오늘은 `542. 01 Matrix`를 다시 보면서,
"왜 `1`마다 BFS를 돌리는 방식이 타임아웃이 나는지"를 정리했고,
정석적으로는 "모든 `0`을 시작점으로 하는 BFS"를 사용해야 한다는 결론을 얻었다.

핵심은 다음과 같다.

- 각 `1`마다 BFS를 돌리면 탐색이 너무 많아진다.
- 시작점이 `0`인 경우가 훨씬 효율적이다.
- 한 번의 BFS로 전체 격자의 최소 거리를 계산할 수 있다.
- 따라서 이 문제는 "multi-source BFS"의 대표적인 예시다.

## 1. 문제 이해
`01 Matrix`는 각 칸이 다음 값을 가진다.

- `0`: 빈 칸, 시작점
- `1`: 거리 계산이 필요한 칸

문제는 각 `1`에서 가장 가까운 `0`까지의 거리를 구하는 것이다.

즉,

- 상태 = 현재 좌표 `(row, col)`
- 전이 = 상하좌우 이동
- 시작 상태 = 모든 `0`의 위치
- 목표 = 각 `1`칸까지의 최소 거리 계산

## 2. 왜 1마다 BFS를 돌리면 안 되나
내가 이전에 쓴 방식은 거의 다음과 같은 구조였다.

```java
for (int row = 0; row < m; row++) {
    for (int col = 0; col < n; col++) {
        if (mat[row][col] == 1) {
            BFS from (row, col);
        }
    }
}
```

이 방식은 문제를 너무 많이 반복한다.

- 격자의 크기가 커질수록 각 `1`마다 BFS를 돌려야 함
- 최악의 경우 `1`이 많으면 BFS가 격자 전체를 반복해서 탐색함
- 결과적으로 너무 많은 중복 계산이 발생한다.

즉,

```text
각 1마다 BFS
=> 중복 탐색 폭발
=> 타임아웃
```

## 3. 정석 아이디어: 0을 시작점으로 BFS
이 문제는 `0`을 모두 시작점으로 두고,
`1`을 거리 계산 대상으로 두는 방식이 정석이다.

왜냐하면,

- `0`은 실제로 가장 가까운 거리를 계산하는 기준이 된다.
- 각 칸의 최단 거리는 결국 가장 가까운 `0`까지의 거리이므로,
- 시작점을 `0`으로 잡으면 한 번의 BFS로 모두 계산할 수 있다.

이걸 그래프로 보면,

- 노드 = 좌표
- 시작 노드들 = 모든 `0` 좌표
- 전이 = 상하좌우 인접 이동
- 거리 = 각 칸이 가장 가까운 `0`까지 이동한 단계 수

## 4. 상태와 상태공간
### 상태
이 문제에서 상태는 다음과 같다.

```text
현재 좌표 (r, c)
```

이 좌표만 있으면,
다음으로 어디로 이동할 수 있는지 계산할 수 있다.

### 상태공간
상태공간은 모든 좌표들의 집합이다.

```text
모든 (r, c) ∈ grid
```

그런데 실제로는,

- `0`은 시작 상태
- `1`은 거리 계산 대상 상태
- 빈 칸은 아직 생각하지 않음

## 5. 왜 이렇게 해야 효율적인가
`1`마다 BFS를 돌리면,
각 칸이 계산될 때마다 같은 주변을 계속 탐색하게 된다.

반면,

- 모든 `0`을 queue에 넣고
- 거리 값을 갱신하면서 한 번에 전파하면
- 각 칸은 최단 거리를 가장 짧게 발견할 수 있다.

그래서 전체 시간 복잡도는

```text
O(m * n)
```

에 가까워진다.

## 6. 정답 코드
```java
class Solution {
    public int[][] updateMatrix(int[][] mat) {
        int m = mat.length;
        int n = mat[0].length;
        int[][] dist = new int[m][n];
        Queue<int[]> q = new ArrayDeque<>();

        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (mat[i][j] == 0) {
                    q.offer(new int[]{i, j});
                    dist[i][j] = 0;
                } else {
                    dist[i][j] = Integer.MAX_VALUE;
                }
            }
        }

        int[][] dirs = {{-1,0},{1,0},{0,-1},{0,1}};

        while (!q.isEmpty()) {
            int[] cur = q.poll();
            int r = cur[0];
            int c = cur[1];

            for (int[] d : dirs) {
                int nr = r + d[0];
                int nc = c + d[1];

                if (nr < 0 || nr >= m || nc < 0 || nc >= n) continue;
                if (mat[nr][nc] == 1 && dist[nr][nc] > dist[r][c] + 1) {
                    dist[nr][nc] = dist[r][c] + 1;
                    q.offer(new int[]{nr, nc});
                }
            }
        }

        return dist;
    }
}
```

## 7. 이 코드의 핵심 포인트
### 1) 시작점이 여러 개인 BFS다
```java
if (mat[i][j] == 0) {
    q.offer(new int[]{i, j});
}
```

모든 `0`이 동시에 시작점이다.

### 2) 거리 갱신이 중요하다
```java
if (mat[nr][nc] == 1 && dist[nr][nc] > dist[r][c] + 1) {
    dist[nr][nc] = dist[r][c] + 1;
    q.offer(new int[]{nr, nc});
}
```

이게 바로 “더 짧은 경로를 발견하면 갱신한다”는 BFS의 핵심이다.

### 3) 최단거리 문제는 BFS로 해결한다
이 문제는 최단 거리 문제다.

그리고 BFS는 같은 레벨을 먼저 처리하기 때문에,
가장 가까운 `0`부터 확산하면서 최단 거리를 계산한다.

## 8. 왜 이 방식이 정석인가
이 문제에서 핵심은,

> 시작점을 어디로 잡느냐

이다.

- 잘못된 시작점: 각 `1`마다 BFS
- 정답 시작점: 모든 `0`을 동시에 시작점으로 사용

이 차이가 전체 실행 시간을 좌우한다.

그래프 관점에서 보면,

- 각 `1`마다 BFS를 돌리는 건 너무 많은 소스 노드를 만들고 탐색을 반복하는 것
- 모든 `0`을 시작점으로 보는 건 한 번의 BFS로 전체 그래프를 효율적으로 탐색하는 것

## 9. 오늘의 결론
이번 문제는 단순히 BFS를 쓰는 게 아니라,

- 무엇이 시작점인지
- 얼마나 많은 상태를 중복 탐색하는지
- 어떤 구조가 최단거리 문제에 적합한지

를 이해하는 문제였다.

즉,

> `01 Matrix`는 "multi-source BFS" 패턴을 배우는 문제다.

이 패턴을 제대로 이해하면,
`994. Rotting Oranges`와도 연결된다.

두 문제 모두,

- 여러 시작점이 있다
- 같은 레벨을 동시에 처리한다
- 최단 거리를 BFS로 계산한다

는 공통점을 갖고 있다.
