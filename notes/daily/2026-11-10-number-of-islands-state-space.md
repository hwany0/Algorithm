# 2026-11-10 Number of Islands: 상태, 상태공간, 그래프 변환

## 오늘의 핵심
`200. Number of Islands`는 단순히 "섬 개수 세기"가 아니라,
"배열 좌표를 그래프의 노드로 보고 연결 요소를 찾는 문제"로 보는 것이 가장 중요하다.

내가 지금 쓴 방식은 아이디어는 맞았지만, 그래프를 직접 구축하는 방식이 너무 무겁다.
그래서 더 간단하고 빠른 형태로 바꾸는 연습이 필요하다.

## 1. 문제를 그래프로 바꾸는 관점
배열의 각 칸은 하나의 상태다.

- 상태: 현재 좌표 `(row, col)`
- 전이: 상하좌우에 있는 칸으로 이동
- 조건: 이동 대상이 `1`인 칸이어야 함

즉, 문제는 아래처럼 해석할 수 있다.

```text
정점(node): 각 '1' 칸
간선(edge): 상하좌우 인접한 '1' 칸 사이의 연결
섬(island): 연결 요소(connected component)
정답: 연결 요소의 총 개수
```

그래프 관점에서 보면,
`numIslands`는 "그래프에서 연결된 컴포넌트 개수를 세는 문제"다.

## 2. 상태와 상태공간
### 상태
이 문제에서 상태는 다음과 같이 정의할 수 있다.

```text
현재 좌표 (row, col)
```

이 좌표만 있으면,
다음으로 이동 가능한 칸을 계산할 수 있다.

- 위로 이동
- 아래로 이동
- 왼쪽으로 이동
- 오른쪽으로 이동

그래서 상태는 정확히 "현재 위치"다.

### 상태공간
상태공간은 모든 가능한 좌표의 집합이다.

```text
(row, col) in [0 ... grid.length-1] x [0 ... grid[0].length-1]
```

여기서 실제로 유효한 상태는 `grid[row][col] == '1'`인 칸들이다.

즉,

```text
상태공간 = 모든 '1' 칸들
```

그리고 이 상태들 사이에 인접 조건을 넣으면 그래프가 된다.

## 3. 왜 연결 요소가 섬인가
동일한 섬 안의 칸들은 서로 상하좌우로 연결되어 있다.

이 연결성은 그래프에서 말하는 "연결된 정점들의 집합"과 같다.

예를 들어:

```text
1 1 0
1 0 1
0 1 1
```

위는 다음과 같이 생각할 수 있다.

- `(0,0)`과 `(0,1)`은 연결됨
- `(0,0)`과 `(1,0)`도 연결됨
- 따라서 같은 섬으로 묶인다.

그래프의 관점에서 보면,
"섬 = 연결 요소"다.

그래서 정답은 연결 요소의 개수다.

## 4. 내가 쓴 코드의 핵심 아이디어
내가 처음 구현한 방식은 이거다.

```java
int[][] direct = new int[][]{{-1, 0},{1,0},{0, -1},{0, 1}};
Map<List<Integer>, List<List<Integer>>> graph = new HashMap<>();
```

핵심 아이디어는 다음과 같다.

- 각 좌표를 그래프 노드로 잡는다.
- 인접한 `1` 칸을 간선으로 추가한다.
- 그 다음 BFS로 연결 요소를 탐색한다.

결론적으로는,
"좌표를 노드로 보고, 섬을 그래프 연결 요소로 확인하는 방식"이 맞았다.

하지만 이 방식에는 몇 가지 문제가 있다.

## 5. 왜 이 방식이 느린가
### 1) 그래프를 직접 만드는 비용이 너무 크다
`Map<List<Integer>, List<List<Integer>>>`는 매우 무거운 구조다.

- 좌표를 `List<Integer>`로 표현하는 것 자체가 비싸다.
- `List.of(row, col)`를 매번 새로 생성한다.
- 각 좌표마다 리스트를 만들고, 그 안에 인접 리스트를 넣는다.
- 결과적으로 불필요한 객체 생성이 많다.

이 문제는 그래프를 직접 만들기보다,
배열 자체를 방문 배열로 관리하는 게 훨씬 더 효율적이다.

### 2) 중복 연결 정보가 많다
각 칸마다 상하좌우를 확인하면서,
인접한 `1` 칸을 반복해서 추가한다.

그런데 같은 연결은 중복될 수 있고,
결국 전체 그래프를 구성하는 비용이 커진다.

### 3) 방문 추적이 `Map<List<Integer>, Boolean>`으로 되어 있음
`List`를 키로 쓰는 방식은 해시 기반 탐색에도 비용이 크다.

이 문제에서는 좌표가 `(row, col)` 쌍이므로,
`int[]` 또는 `visited[row][col]`처럼 단순한 방식이 더 적합하다.

## 6. 더 좋은 패턴: 배열 기반 BFS/DFS
이 문제는 그래프를 실제로 직접 만드는 대신,
배열 기반으로 BFS/DFS를 바로 수행하는 게 가장 깔끔하다.

```java
class Solution {
    public int numIslands(char[][] grid) {
        int n = grid.length;
        int m = grid[0].length;
        boolean[][] visited = new boolean[n][m];
        int[][] dirs = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};
        int count = 0;

        for (int row = 0; row < n; row++) {
            for (int col = 0; col < m; col++) {
                if (grid[row][col] == '1' && !visited[row][col]) {
                    count++;
                    Queue<int[]> q = new ArrayDeque<>();
                    q.offer(new int[]{row, col});
                    visited[row][col] = true;

                    while (!q.isEmpty()) {
                        int[] cur = q.poll();
                        int r = cur[0];
                        int c = cur[1];

                        for (int[] dir : dirs) {
                            int nr = r + dir[0];
                            int nc = c + dir[1];

                            if (nr >= 0 && nr < n && nc >= 0 && nc < m) {
                                if (grid[nr][nc] == '1' && !visited[nr][nc]) {
                                    visited[nr][nc] = true;
                                    q.offer(new int[]{nr, nc});
                                }
                            }
                        }
                    }
                }
            }
        }

        return count;
    }
}
```

### 이 코드의 상태 해석
- 상태: 현재 좌표 `(r, c)`
- 전이: 상하좌우로 이동
- 방문 여부: `visited[r][c]`
- 연결 요소: BFS/DFS로 묶인 영역

즉, 그래프를 직접 만들지 않고도,
그래프의 연결 요소를 그대로 탐색하는 형태다.

## 7. 정리
### 이 문제에서 중요한 개념
- 상태 = 현재 좌표
- 상태공간 = 모든 좌표
- 전이 = 상하좌우 인접한 `1` 칸 이동
- 섬 = 연결 요소
- 문제의 핵심 = 그래프에서 연결 컴포넌트 개수 세기

### 내가 처음 구현한 방식의 장점
- 그래프 개념을 정확히 적용하려고 한 점은 좋았다.
- 상태, 전이, 연결 요소를 문제에 맞게 잡았다.

### 하지만 개선해야 할 점
- `List<Integer>`를 키로 쓰는 것은 비효율적이다.
- 그래프를 전체 생성하는 방식은 너무 무겁다.
- 배열 기반 BFS/DFS가 훨씬 자연스럽고 빠르다.

## 8. 결론
`200. Number of Islands`는
"그래프를 직접 만드는 형태"로도 풀 수 있지만,
실전에서는 "배열을 그래프로 간주하고 BFS/DFS로 탐색하는 방식"이 정석이다.

이 문제에서 핵심은 다음 한 문장이다.

> 각 칸은 노드이고, 상하좌우 연결된 '1' 칸은 간선이며, 섬은 연결 요소다.

이 개념을 잡으면 이후 Tree / Graph / BFS 문제도 훨씬 쉽게 보인다.
